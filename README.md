# Roomay

**Roomay** is a Workpeg-native hotel operations and AI guest-experience prototype.

The initial scaffold currently renders **Hello from roomay**. Real hospitality workflows, guest identity verification, and Workpeg data integration are planned but not implemented yet.

WOR-8 Phase A adds an [offline hotel model](docs/hotel-model.md), synthetic fixtures
and pure rule tests. Hosted tables and persistence remain unverified under WOR-6.
Run `python -m unittest discover -s tests -v` to verify the offline rules.

## Project structure

```text
workpeg.json          Peg manifest (namespace, optional functions, runtime)
ui/main.py            Workpeg Python UI and routes
function/             Optional Python functions (not required for UI smoke test)
requirements-dev.txt  Tested local Workpeg SDK version
CONTRIBUTING.md       Team collaboration and Linear workflow
```

## Local development

Prerequisites: Python 3.10+ and the Workpeg SDK. The initial setup was verified on Windows with Python 3.13.5 and Workpeg 0.149.1.

From the **repository root**, where `workpeg.json` lives:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
workpeg doctor . --offline
workpeg ui serve ui/
```

Open the local URL printed in the terminal (on the initial Windows setup, `http://localhost:8081`). For a compile check, in a separate shell with the virtual environment activated:

```powershell
workpeg ui build ui/
```

Compiled assets in `ui/dist/` are intentionally ignored by Git.

macOS/Linux: use `python3 -m venv .venv` and `source .venv/bin/activate` before installing requirements.

## Workpeg functions and publishing

The generated `function/` directory is present for optional server-side logic, but **the initial project does not require running functions**. The autogenerated `workpeg run` reference is outdated; use the official [Workpeg Functions documentation](https://developers.workpeg.com/docs/latest/functions/) to find commands appropriate to the installed SDK.

Publishing requires separate Workpeg developer access and review. This repository is currently only a local prototype plus GitHub source; the Workpeg Peg is **not** claimed to be published.

## Data safety

Work only in a dedicated Workpeg test business with synthetic guest, booking, and room data. The SDK's `--fake-cloud` mode may still write to Workpeg's real service. Do not commit `WORKPEG_PK`, API keys, local `.env` files, or real customer records.

Hotel reservations and check-ins are different states. Any future guest-facing APIs must securely verify stay ownership and never expose privileged Workpeg credentials to browsers.
